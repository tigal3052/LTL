# Node Select Crossroads Redesign Design

## 목표

노드 선택 화면을 단순한 로드맵 보드가 아니라 "레비아탄 내부에서 갈림길을 고르는 지도"처럼 느껴지도록 전면 재구성한다. 첫 스테이지는 고정 출항 스테이지로 처리하고, 다섯 개의 노드 선택은 두 번째 스테이지부터만 노출한다.

## 현재 구조 요약

- 런타임 페이지 본체는 `app-LTL/src/scenes/pages/NodeSelectRuntimePage.gd`와 `.tscn`이 담당한다.
- 페이지는 `selectedLeviathan`, `stageIndex`, `maxStages`, `nodeSelect.candidates`, `selectedNodeIndex`, `pageHeroPath`를 `apply_state()`로 받는다.
- 현재 문제는 세 가지다.
- 상단 헤더가 여전히 `"노드 선택 페이지"` / `"로드맵 보드"` 문구를 중심으로 잡혀 있다.
- 1스테이지부터 5개 후보를 같은 방식으로 보여줘서 "출항"과 "갈림길"이 구분되지 않는다.
- 고정 높이 캔버스와 회전된 `ColorRect` 라인 때문에 페이지가 아래로 넘치고, 일부 시각 요소의 바운딩 박스가 뷰포트를 벗어난다.

## 디자인 방향

### A. Compass Gate

- 커다란 원형 항로판과 나침반 같은 중심축을 둔다.
- 고정 출항과 이후 갈림길을 같은 축 위에서 설명하기 좋다.
- 다만 레비아탄 침투 감각보다는 항해 UI 인상이 강하다.

### B. Tide Fork

- 시작점에서 위로 뻗다가 2스테이지부터 다섯 갈래로 퍼지는 거대한 분기 팬을 만든다.
- 1스테이지 고정 출항 규칙을 가장 자연스럽게 보여준다.
- 선택 노드가 "지도 위 갈림길"처럼 보이기 쉽고, 현재 데이터 구조와도 잘 맞는다.

### C. Leviathan Spine

- 중앙 척추 축과 좌우 갈비처럼 분기하는 구조를 쓴다.
- 레비아탄 내부를 훑는 감각은 강하지만, 단계 정보와 선택 후보를 읽는 난이도가 조금 올라간다.

## 추천안

`B. Tide Fork`를 추천한다.

- 현재 `stageIndex` 흐름과 가장 직결된다.
- 첫 스테이지는 아래쪽 출항 노드 하나만 보여주고, 둘째 스테이지부터 좌우로 팬처럼 벌어지는 5개 후보를 만들 수 있다.
- 선택 후보가 바뀌어도 버튼/캡션/상세 요약만 갱신하면 되므로 동적 구성 대응이 단순하다.

## 적용 규칙

- 히어로 타이틀은 선택된 레비아탄 이름으로 고정한다.
- `"노드 선택 페이지"`와 해당 설명 문장은 제거한다.
- `"로드맵 보드"`와 해당 설명 문장은 제거한다.
- 1스테이지는 고정 출항 스테이지다.
- 1스테이지에서는 클릭 가능한 현재 경로 버튼을 렌더링하지 않는다.
- 2스테이지 이상에서는 현재 단계의 5개 후보 버튼을 렌더링한다.
- 하단 정보 문구는 선택 경로 상세 또는 고정 출항 안내만 짧게 보여준다.
- 항로 선은 `Control` 자식 회전 사각형 대신 `Line2D`로 그려 레이아웃 검사 시 바운딩 박스 문제가 생기지 않게 한다.
- 캔버스 최소 높이와 내부 여백을 줄여 `ActivePhaseContainer` 안에서 완전히 수납되게 만든다.

## 검증 포인트

- 1스테이지 진입 시 히어로 타이틀이 선택 레비아탄명인지
- 1스테이지 진입 시 route button 수가 0인지
- 2스테이지 진입 시 route button 수가 5인지
- 노드 선택 페이지의 보이는 컨트롤이 게임 뷰포트 하단을 넘지 않는지
