사용 방법

  1. 비 trivial 작업 전 final-goal.html과 이 파일을 먼저 읽는다.
  2. 작업 범위를 최소 하나의 objective id에 연결한다.
  3. 현재 카드가 너무 추상적이면 새 objective를 추가하거나 기존 카드에 세부 목표를 보강한다.
  4. 자동 테스트, 하네스 게이트, 또는 명확한 수동 검증 근거가 있을 때만 completed로 바꾼다.
  5. 완료 보고와 worklog에는 변경한 objective id와 검증 증거를 함께 적는다.

상예정Backpack Engine

아이템 형태와 비콘 패턴을 명확한 백팩 빌드 문법으로 만든다

현재의 같은 색 인접/비콘/일부 relic 링크 기반을 유지하면서, 폴리오미노 형태와 비콘 영향 범위가 전투 효과의 조건으로 읽히도록 대표 패턴을 추가한다. 에너지 큐의 기본 평균 쿨타임·쿨타임 정렬·로테이션 규칙은 변경하지 않는다.

  • 세로/가로/ㄱ자/T자 등 최소 2개 shape family가 타일 연속 타격, 같은 행·열 대응, 특정 배치 조건 피해/쿨다운 보너스 등으로 구분되어야 한다.
  • 비콘은 기존 같은 색 인접 규칙을 유지하되, 십자/라인/릴레이처럼 읽기 쉬운 최소 1개 추가 패턴을 지원하고 툴팁/read model에 영향 범위를 표시한다.
  • 큐 순서 자체를 위치 규칙으로 재정의하지 않는다. shape/비콘 패턴은 damage, effective cooldown, token modifier, beacon pulse처럼 기존 큐 입력값에만 영향을 준다.
  • 검증은 별도 추상 목표가 아니라 1/2의 수용 기준으로 둔다: 같은 아이템이라도 승인된 shape/비콘 패턴 배치가 실제 전투 피해·쿨다운·토큰 modifier 중 하나 이상을 다르게 만든다는 테스트와 UI 설명을 남긴다.
  • 2026-06-28 - 사용자 검토 반영: shape 의미화와 비콘 패턴 확장은 승인, 에너지 큐 위치 기반 우선순위 변경은 반려하고 기존 큐 규칙 유지로 범위를 고정.
