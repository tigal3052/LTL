Looting The Leviathan / project north star / 모든 작업의 판단 기준

최종 목표 핵심

플레이어가 거대 레비아탄의 몸 위에서 백팩 엔진을 설계하고, 흘러가는 파동 리듬을 읽어 직접 채굴하며, 4핀 시간 압박 속 생존·보상·성장 선택으로 다음 원정을 재구성하는 실시간 엔진 빌딩 생존 채집 로그라이크를 알파 수준의 반복 가능한 세로 슬라이스로 완성한다.

작성/갱신: 2026-06-27

절대 보존해야 할 핵심 재미

1. 백팩 엔진 빌딩

폴리오미노 유물·드릴·비콘을 제한된 그리드에 배치하고, 인접/형태/색상 시너지로 전투 리듬이 달라져야 한다.

2. 파동 읽기와 수동 채굴

3x10 지형 그리드의 파동 흐름을 읽고, 에너지 큐의 토큰을 어느 타일에 언제 발사할지 직접 판단하게 만든다.

3. 4핀 시간 압박

방해 요소는 불합리한 체력 손실이 아니라 채굴 시간을 지연시키고, 실패는 시간 경과로 핀이 빠지는 긴장으로 표현한다.

4. 탐욕의 기회비용

미래의 강한 유물을 챙길지, 현재 파동/노드에 맞는 효율 배치를 택할지의 공간·시너지 선택이 매 런의 딜레마가 된다.

5. 보상과 재구성

채굴 성공 직후의 보상 공개, 스탯 롤, 융합, 다음 노드 선택이 다음 빌드를 설계하는 설렘으로 이어져야 한다.

6. 금기와 복수의 서사

초기 알파 이후에는 “레비아탄 채집은 허용, 사냥은 금기”라는 LTL 규율과 주인공의 복수심을 시스템 진행과 연결한다.

모든 작업 전 확인 질문

  • 이 변경이 백팩 엔진 빌딩, 파동 수동 채굴, 4핀 시간 압박 중 최소 하나를 더 명확하게 만드는가?
  • 캐릭터/레비아탄 선택 → 노드 선택 → 채굴 전투 → 보상/융합 → 다음 노드/클리어/패배/재시도 루프를 깨지 않는가?
  • 결정성, 데이터 주도 설계, 테스트 계약, 텔레메트리 중 어떤 증거로 검증할 수 있는가?
  • UI/연출은 최근 디자인 방향인 하늘·초록·석재·고대 유적 탐사 감각을 강화하는가?
  • 강한 보상 연출을 만들더라도 과도한 섬광·흔들림·도박적 near-miss를 피하고 접근성을 보존하는가?
  • 완료 후 docs/project-goals/work-objectives.html의 관련 목표를 세분화하거나 완료 처리했는가?

현재 상태 요약

구현 축

Godot 프로젝트는 전투·보상·노드·UI 런타임과 90개 이상의 GDScript 테스트를 갖춘 상태이며, 최근 작업은 M8 세로 슬라이스와 EnergyToken 기반 드릴/비콘/롤/융합 계약에 집중되어 있다.

검증 축

프로젝트 로컬 하네스와 범용 하네스가 source-map, request-analysis, size, transition, worklog-token 게이트를 제공한다. 앞으로 목표 관리도 같은 하네스 흐름에 포함한다.

다음 큰 전환

현재 목표는 이미 만든 세로 슬라이스를 “알파로 확장 가능한 기준선”으로 고정하는 것이다. 신규 기능보다 루프 안정화, 읽힘, 밸런스 기준, 작업 목표 갱신을 우선한다.
